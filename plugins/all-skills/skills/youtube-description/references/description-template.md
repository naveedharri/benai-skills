## The four standing links

Only these four of the six UTM destinations appear in the description:
accelerator, free, aioperator, agency. Cowork and Kit-YouTube are generated by
`benai-utm-creator` for other placements and do **not** go in the description.

### Link order follows what Ben promises on camera

Added 2026-08-26, and it overrides the template's default order.

The template lists the accelerator first. But Ben regularly says on camera **"the first link in
the description below"** while talking about the free resource. When he does, the free block has
to move to the top, above the accelerator. A viewer takes him literally, clicks the first link,
and lands on a sales page instead of the thing they were promised.

So: check the transcript for what Ben calls the first link, and order the blocks to match him.
This is not a style preference, it is the difference between the description keeping his promise
and breaking it.

It caught the team out on 2026-08-26 and had to be fixed by hand in Studio after the description
was already written. `youtube-chapters-tags` step 5 already reports what Ben references, so the
information is available before assembly. Use it.

**A note for whoever edits the video:** write down every promise Ben makes about a link while you
are cutting. "First link in the description", "I have a separate video on that". Those two
sentences are what the 📺 block and the link order are built from, and they are much cheaper to
catch in the edit than after publishing.

### When there is no lead magnet, the free block comes out

Added 2026-08-25. The `-free` link points at `benai.kit.com/<code>-free`, a Kit page that only
exists if the lead magnet was built. With no lead magnet, that page was never created and the
link resolves to nothing.

So when the Ship Brief says no lead magnet, delete these two lines and the blank line after
them:

```
Get the free setup guide ⤵️
https://c.benai.co/{{CODE}}-free
```

Three `c.benai.co` links then remain, not four, and the substitution check has to expect three.
Do not leave the block in with a dead link, and do not point it at a previous video's Kit page.

This happened for real on code `tnwtb`. Oskar's call was to cut the block.

## {{REFERENCED_VIDEOS}}

This block is **not** boilerplate. It is the videos Ben actually points to in the current
video, so it changes every time and sometimes shrinks or grows.

Each entry is two lines:

```
Claude Skills Tutorial 📺
https://youtu.be/X3uum6W2xEI
```

Rules:
- Source the list from `youtube-chapters-tags`, which flags every video Ben references in
  the body. One of them is normally the end-card video.
- The label is what Ben calls it on camera, not the video's full YouTube title.
- If Ben references nothing by name (for example he only says "check out the video above"),
  do not silently carry the previous video's list forward. Ask which videos to link, and
  offer 5 candidates from the channel that fit the topic.
- Blank line between entries. No blank line between label and URL.

```
Claude Skills Tutorial 📺
```

## Formatting rules

- The arrow is `⤵️` (U+2935 + VS16, "rightwards then curving downwards"), not `⬇️` and not
  `⤴️` (U+2934, which curves *up*). Copy it, do not retype it.
- The TV is `📺` (U+1F4FA).
- Blank line between every labelled block.
- No em dashes anywhere. Chapter separators are en dashes (`–`), which is different.
- Character cap 5000. Report the count.

## The substitution check

Before writing anything into Studio, assert the assembled block contains **exactly** the
expected number of `c.benai.co` links, all carrying the current code:

- Four, when there is a lead magnet.
- Three, when there is not.

A count that is off by one means either the free block was handled wrongly or a previous
video's code survived the assembly. Both have happened. Stop and report rather than writing.

Also assert the old code appears zero times. Pasting a previous video's description is how the
wrong code ships, and this check is the thing that catches it.
