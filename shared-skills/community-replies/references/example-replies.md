## Technical / how-to

> So currently we don't have active triggers in Claude Cowork, we only have Schedules. What you can do is schedule an automation every five minutes or every hour where it goes and checks your email, and if there's a new one it drafts a response. It can use connectors directly from Cowork. The only catch is your laptop has to stay on for it to run.
>
> The other option is via n8n, also easy. The flow would be: 1) a Gmail trigger that listens for the latest email from a specific sender, 2) it pulls the relevant info from your CRM, 3) it drafts the email with Claude or OpenAI. Feel free to schedule a #1:1 Live Tech Call if you need help with either.

> If you're using subagents, there's an option to limit the max turns a subagent runs, so it doesn't fire off too many API calls on behalf of your Claude instance.

## Bug / troubleshooting

> Hey Sabahudin, here's what's happening. I've been having the same problem myself. Every Claude session spins up a virtual machine inside the Cowork desktop app, and over time these VMs become dead weight and sometimes crash the app. I've had to clean up 18GB of old VM assets and sessions, and sometimes a hard restart of Cowork is enough to get it working. There are bugs, but you can work around most of them.

> You can see in the error it says the checksum failed, so this is on the node side. When you install a community node, n8n runs a checksum for security and compatibility, and that's what's failing, so the connection isn't establishing properly. I'd check if the community node has an update in the admin panel, update it, and add it again.
