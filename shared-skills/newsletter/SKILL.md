# Ben's Newsletter Writer

An iterative, creative workflow for writing newsletters in Ben's authentic voice.

## Critical Rules

1. **NEVER output a complete newsletter immediately.** This is a step-by-step creative process. At each step: provide suggestions, wait for Ben to decide, only then proceed.
2. **ALWAYS read the specified context documents at each step.** Each step lists REQUIRED READING. Do not skip it.
3. **Write only from the provided context documents.** Do not invent strategies, stories, facts, or stylistic habits not evidenced in the inputs.

## Context Documents Location

All documents are in the `references/` folder bundled with this skill:
- `references/01_Ben_Profile_Background.md` - Ben's story, credentials, values
- `references/02_What_We_Do_Offer.md` - The offer and value proposition
- `references/03_ICP_Ideal_Customer_Profile.md` - Target audience details
- `references/04_Voice_Personality.md` - Tone and messaging
- `references/05_Newsletter_Strategy.md` - Positioning and core beliefs
- `references/06_Frameworks_and_Patterns.md` - Outline frameworks, subject line and hook patterns
- `references/07_Writing_Framework.md` - Voice DNA, voice modes, writing method, checklist
- `references/08_Newsletter_Examples.md` - Real newsletter examples to mimic

Read only the file(s) a step names. Do not read all references up front.

## The 7-Step Process

### Step 1: Input Analysis

**REQUIRED READING:** None yet. Just analyze the input.

Determine input type and clarify scope.

**If YouTube transcript:**
- Ask: "Do you want to repurpose the entire video or focus on a specific insight/section?"
- If specific section: ask which part or let Ben specify
- Extract the core insight(s) from the selected content

**If insight/idea:**
- Confirm understanding of the insight
- Ask clarifying questions if the insight is vague

**Output:** Clear statement of the core insight to build the newsletter around.

**STOP. Wait for Ben to confirm before proceeding.**

---

### Step 2: Define Outcomes

**REQUIRED READING:**
- `references/03_ICP_Ideal_Customer_Profile.md` - who we write for and their pain points
- `references/05_Newsletter_Strategy.md` - align outcomes with positioning and core beliefs
- `references/04_Voice_Personality.md` - align outcomes with the message people carry away

Define the main takeaway and secondary outcomes for the ICP, considering all three audience angles in the ICP document (ambitious solopreneurs, career pivoters, exploring entrepreneurs).

**Main Outcome Options (suggest 3-5):**
Format each as: "After reading this, the reader will [specific transformation/realization/action]"

Outcome types to consider: mindset shift, action trigger, knowledge gain, belief change.

**Secondary Outcomes (suggest 2-3 per main outcome):** supporting transformations that reinforce the main message.

**STOP. Wait for Ben to select/modify main + secondary outcomes.**

---

### Step 3: Suggest Newsletter Outlines

**REQUIRED READING:**
- `references/06_Frameworks_and_Patterns.md` - outline frameworks, presentation template, "every outline must include" rules
- `references/01_Ben_Profile_Background.md` - which stories/experiences fit
- `references/07_Writing_Framework.md` - the 3 voice modes and emotional temperature
- `references/08_Newsletter_Examples.md` - the section patterns in real examples

Propose **at least 3 outline options**. Each outline defines the framework, sections, their purpose, and the flow. This is where the shape of the newsletter gets decided: Ben picks the structure, then writing follows.

Use the frameworks, presentation template, voice-mode mapping, and story-weaving guidance in `references/06_Frameworks_and_Patterns.md`. Each outline should feel genuinely distinct.

**STOP. Wait for Ben to pick, combine, or modify outlines before writing.**

---

### Step 4: Subject Lines

**REQUIRED READING:**
- `references/06_Frameworks_and_Patterns.md` - subject line patterns and the 5-7 mix to generate
- `references/08_Newsletter_Examples.md` - real subject line examples
- `references/05_Newsletter_Strategy.md` - align with positioning and core beliefs
- `references/04_Voice_Personality.md` - confident, direct, not clickbaity
- `references/03_ICP_Ideal_Customer_Profile.md` - resonate with audience pain points and desires

Now that the outline is locked, generate subject line options per `references/06_Frameworks_and_Patterns.md`, each with a suggested preview text. Present all options.

**STOP. Wait for Ben to select/combine.**

---

### Step 5: Suggest Hook Options

**REQUIRED READING:**
- `references/06_Frameworks_and_Patterns.md` - hook patterns and length guidance
- `references/08_Newsletter_Examples.md` - how real newsletters open (first 5-10 lines of each)
- `references/07_Writing_Framework.md` - hook patterns, voice modes, emotional temperature (opening is "cool but relatable")
- `references/01_Ben_Profile_Background.md` - authentic story details, failures, experiences
- `references/04_Voice_Personality.md` - tone calibration (confident not arrogant, vulnerable not weak)

Present **3-5 hook options** that fit the selected outline, following the hook patterns in `references/06_Frameworks_and_Patterns.md`. Each hook must flow naturally into the first section of the selected outline.

**STOP. Wait for Ben to pick a hook.**

---

### Step 6: Write the Newsletter

**REQUIRED READING (read all):**
- `references/08_Newsletter_Examples.md` - when populated, mimic these closely so the newsletter sounds exactly like Ben. If it is still the empty placeholder, follow its fallback instruction and build voice from 07 and 04 instead.
- `references/07_Writing_Framework.md` - prime directives, input precedence, writing method, and the Voice & Structure Checklist
- `references/01_Ben_Profile_Background.md` - authentic story details and credentials
- `references/02_What_We_Do_Offer.md` - accurate P.S. pitch content
- `references/04_Voice_Personality.md` - signature phrases and messaging

Follow the Writing Method in `references/07_Writing_Framework.md` in order. Write the complete draft, run the Voice & Structure Checklist there, and fix every miss before presenting.

**STOP. Present draft and be ready to iterate based on Ben's feedback.**

---

### Step 7: Iterate

After presenting the draft, be ready for feedback. This is where the newsletter gets polished. Ben may want to adjust tone, swap sections, add stories, or rework specific paragraphs. Follow the Iteration Protocol below.

---

## Iteration Protocol

At any step, if Ben wants to revise:
1. Acknowledge the feedback
2. Re-read relevant context documents if needed
3. Provide revised options based on direction
4. Wait for new lock-in before proceeding

The iterative process IS the value.

## Self-improvement

This skill is never finished. Improve it as you use it.
- When Ben corrects how a step was done, update the relevant reference file (or this SKILL.md) so the correction sticks. Do not just fix it for this run.
- When a correction is a hard rule ("always X", "never Y"), add it as a permanent rule here.
- When Ben says a newsletter was genuinely good, save it to `references/08_Newsletter_Examples.md` so it becomes a model for future runs.
- Keep the skill small: when you add something, run the deletion test and cut anything that no longer changes behavior.
